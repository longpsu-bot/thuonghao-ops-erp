## Rules: classify before deciding whether to stop

1. **Test-source defect:** malformed fixture, stale expected command/selector, inconsistent runner invocation. Make the smallest exact-source correction and retain the same business assertion. No new Owner approval for this approved bounded CI repair.
2. **Test-environment or asynchronous harness defect:** reproduce, await an observable state/controlled event, check cleanup/clock/focus; repair determinism without skipping the test, weakening assertions or silently raising a timeout.
3. **Application/runtime defect:** make a narrowly supported fix only inside the approved #392 recovery scope if it restores the existing contract; escalate any changed business/API/DB/capability semantics or broad redesign. A genuine defect is not made acceptable by relabeling it a flaky test.
4. **Performance failure:** measure whole-command work, nested calls, repeated SQL, query plans and lock waits *before* proposing optimization. Do not attribute a slow frame to a specific SQL function without evidence.
5. **Policy / business safety failure:** STOP and request Owner decision. Do not waive exact quantities/Units, supplier/School identity and authorization, transactional Save, dirty/UNKNOWN guards, immutable released PO/PXK, audit, concurrency or historical continuity.

**STOP means stop the failing strategy, not prohibit a documented test-fixture fix.** One targeted correction cycle is allowed; if the same root failure survives two well-defined attempts, stop with minimal reproducible evidence and a next decision. No indefinite optimization/retry.
