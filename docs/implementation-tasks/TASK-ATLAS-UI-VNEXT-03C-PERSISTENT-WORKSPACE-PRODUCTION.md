### Required behavior

1. Define a static application registry conceptually containing id/label/icon/group/render; reuse current capability IDs and Vietnamese labels. Generate a compact **Bàn làm việc** launcher for all available destinations, separate from open-workbench tabs. Include simple local label search, quiet open status and exactly the two groups below; no business drafts/state or detailed dirty/attention in the launcher. Successful selection opens/activates or activates-existing without duplication, closes the launcher and restores trigger focus. Support keyboard search/traversal/activation and Escape. Replace the primary permanent icon rail. One compact shell utility owns user/environment/sign-out, without duplication in the launcher. No descriptor entity/class/lifecycle persistence.
2. Local reducer owns only ordered unique open IDs and active ID. Workbenches own drafts, quantities, Supplier, filters/search, API results, commands, validation, currentness and business state. Keep any status reports, guard handles and mount seeds minimal and separate from reducer business facts.
3. Launch unopened once; repeated launch activates existing instance. Persist keyed panels while open. Switch performs no exit, unmount, initialization read or refresh, including dirty switches. Preserve input identity/value, scope/date, stage, selected detail and local scroll.
4. Close makes the owner visible and calls its existing guard; remove only on approval. Preserve cancel/block, Save/discard/cancel and busy/Review/stale/unknown locks; restore focus after dialog cleanup. No universal Save or automatic discard.
5. Add explicit owner-to-workspace ordinary/unsaved/optional-attention callbacks. Report from the actual local dirty sources through capability wrappers. No DOM scraping, MutationObserver or serialized drafts. Recipe metadata creation/editing, base composition and change orders must report precisely; an unchanged open form is not falsely dirty and an edited hidden form is not falsely clean.
6. Block voluntary sign-out if any open owner is unsaved; list/focus the owners needing individual resolution. Attempting sign-out discards nothing. Preserve non-destructive unresolved-command/Auth safeguards; never traverse destructive exit callbacks as a global preflight. Keep hidden-owner `beforeunload` protection.
7. Seed operational date on first open only; preserve each existing local date/stage on activation. Planning capability must own its context independently of whichever other workbench last reported a date. Preserve Recipe as-of date and reconciliation range. Internal job/scope changes keep their existing guards.
8. Need continuation opens unopened Procurement at exact Need date/Allocation stage. Existing Procurement is activated intact, including dirty selected detail and Orders stage; disclose intended versus retained date/stage when different. Do not remount, change keys or silently force context. Add `requestContext(...)` only if a demonstrated requirement warrants a separately reviewed guarded interface. Activation remains navigation, not a business command.
9. Keep APIs/Auth inputs stable; audit all mounted read effects, subscriptions, timers and late-response ownership. Recipe change orders' Vietnam-midnight timer specifically needs proof. A hidden read completion may settle safely; hidden or activation refresh may not overwrite draft/Review/unknown recovery. No global cache/background sync.
10. Hidden panels are visually hidden/inert, absent from active landmarks and unreachable to focus/commands. Dismiss escaping nonmodal UI, and resolve a modal before deactivation so no hidden focus trap/scroll lock remains. Investigate the existing portal root with persistent siblings; choose bounded UI containment, not a provider/system reboot.
11. Implement named workspace tab relationships, selected state and roving Arrow/Home/End navigation, active reveal, keyboard close and visible post-switch/post-close focus. Narrow widths separate **Bàn làm việc** (launcher) from **Đang mở** (open selector with active/unsaved/attention labels and reachable close), with 44px touch targets. Do not squeeze desktop tabs or a permanent rail onto mobile.
12. Certify 12-tab capacity with test-only descriptors where needed: every ID reachable, local strip overflow, whole active-tab/close reveal, readable Vietnamese labels and all options reachable narrowly. Do not ship illustrative future modules.
13. Pass DATEPICKER_WORKSPACE_GATE with several mounted date controls: only the active owner exposes a calendar; switching dismisses transient date UI; inactive panels receive no focus/input; selection stays owner-local; activation changes no date; no hidden popup/focus trap survives switch/close; browser checks pass. Per explicit owner clarification on 5 October 2026, NVDA/JAWS, screen-reader/spoken-date/live-announcer human certification and WCAG certification are excluded from release acceptance.

## Prohibited changes and security review

No new business concepts, module boundaries, daily stages, status lifecycles, command semantics, rounding/quantity precedence, official numbering, released-document recalculation, immutable evidence or API contracts. No automatic business Save/release, global Save/Discard, sequential destructive sign-out, workspace restoration, tab groups/pinning/favorites/recently-used/customizable groups, multi-window or multi-instance dates. No command-palette dependency, nested navigation framework, new dependencies, Chakra re-bootstrap, replacement system/provider, legacy presentation imports, disabled tests or weakened CI.

Default **Supabase changes 0; Retool changes 0; business-contract changes 0; hosted writes 0**. If implementation proves a backend change necessary, stop that scope and document a separately reviewed task; UI cannot silently broaden it. Keep Auth subject isolation, no service-role credentials, existing RLS/capability/scope enforcement, exact commands/idempotency/concurrency and unknown-outcome protection. UI visibility is not authorization. Auth expiry/identity changes must not expose the preceding user's mounted state or issue unintended commands.
