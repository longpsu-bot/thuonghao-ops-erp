## 1. Decisions already established by the task

The following directions are authoritative prerequisites for future design:

- calculation precision, comparison epsilon, ratio precision, Planning step, purchase step, persisted precision and display precision are distinct;
- upward purchase quantization never produces less than confirmed need;
- supplier portions are exact multiples of their effective step;
- PO and Dispatch consume the same exact committed allocation snapshot;
- final confirmation, persisted command result and authorized readback are exactly equal;
- React does not own authoritative quantity arithmetic;
- released facts are corrected through explicit revision, not silent recalculation.

These directions do not approve a function, schema, algorithm implementation or rollout.

The accepted lifecycle remains wholesale source → released Confirmed Need Batch/line revisions → CMD-03 creates Purchase Handoff directly as `RELEASED_TO_PROCUREMENT` version 1 → CMD-04 creates a released Dispatch Requirement. PA-06D does not insert an approved object into that path.

## 3. Write-fidelity decision

Future commands must implement one canonical calculation path for preview and commit. Preview returns exact operational values, tick counts, residual decisions, `preview_id`, `preview_hash`, source/aggregate versions and `rule_set_version`. Commit accepts the preview identity plus the same expected versions; it does not accept client-recalculated portions as authority.

On success, command output contains the exact persisted snapshot. The client discards its proposal, renders the returned values and performs an authorized readback. A mismatch blocks PO/Dispatch progression. Exact replay returns the same result; changed intent uses a new idempotency key and a new preview. Ambiguous transport is resolved from command outcome/readback before any retry.

## 4. Consequences and non-decisions

- The existing PA-05E full-line allocation remains valid only for its approved bounded supplier-direct slice; it does not authorize multi-supplier portions.
- PA-06E resolves the preferred insertion point as the existing Confirmed Need line revision before CMD-03, without a separate Quantity Decision object. CMD-03 consumption changes still require an explicit architecture and command-contract change.
- A new intermediate object between Confirmed Need and Purchase Handoff is an alternative architecture change, not an approved PA-06D object.
- `Nhu cầu vận hành` is **Proposed pending product-owner and operations-language review**; PA-06D records alternatives but does not settle the final Vietnamese term.
- No implementation may infer approval for the candidate Planning steps, residual policy, locks, automatic supplier proposal, zero behavior or released-PO correction path.
- No direct table access, Retool orchestration, destructive family replacement, client-authored rounding or client-authored rebalancing is authorized.
- No new API function or registry change is authorized by this decision document.
- H1A preparation does not settle Procurement purchase steps, supplier allocation quanta, residual ordering, PO correction, or Dispatch commitment. H1A SQL, H1B1, and H1B2 remain separately unapproved.
